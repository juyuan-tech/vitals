# Module Reference

**English** | [中文](modules.md)

vitals is made up of 61 modules; `vitals --list-modules` lists all of them. Each module independently collects one piece of information, with no dependencies between them; `--sources` shows **which files** each module actually read during this run (recorded at runtime, not a hand-written source table). This document groups the modules by topic and explains what each module shows, under what condition it has data, and its evidence files. In each entry, "Files actually read" is copied verbatim from the runtime record of `--sources`; for modules that say "No files read", the data comes from environment variables or system calls.
> Note: the paths listed in each entry are the runtime records of `--sources` on the author's machine. Paths containing `$HOME/` expand according to your own home directory; some modules read certain files only under specific desktop environments (for example GTK's `settings.ini`).

## System Identity and Host Information

- **os** — distribution name.
  Files actually read: `/etc/os-release`
- **host** — machine model, from DMI.
  Files actually read: `/sys/devices/virtual/dmi/id/sys_vendor`, `/sys/devices/virtual/dmi/id/product_name`, `/sys/devices/virtual/dmi/id/product_version`, `/sys/devices/virtual/dmi/id/board_name`
- **kernel** — kernel version; it goes through `uname(2)` (via rustix's safe wrapper) rather than reading `/proc/sys/kernel/osrelease`, so it is not tied to Linux.
  Files actually read: No files read (data comes from environment variables or system calls)
- **bios** — firmware information, from DMI; the key carries `UEFI` / `BIOS`, the evidence being whether `/sys/firmware/efi` exists — the same piece of firmware information means completely different things under the two boot modes.
  Files actually read: `/sys/devices/virtual/dmi/id/bios_version`, `/sys/devices/virtual/dmi/id/bios_vendor`, `/sys/devices/virtual/dmi/id/bios_date`
- **board** — motherboard model, from DMI.
  Files actually read: `/sys/devices/virtual/dmi/id/board_name`, `/sys/devices/virtual/dmi/id/board_vendor`, `/sys/devices/virtual/dmi/id/board_version`
- **chassis** — chassis type (laptop / desktop / server…), from DMI; the DMI chassis type is more reliable than inferring indirectly from things like `/sys/class/power_supply/*`.
  Files actually read: `/sys/devices/virtual/dmi/id/chassis_type`
- **version** — this program's own version and build target; all values come from compile-time constants and do not change at runtime, and the platform uses `std::env::consts` rather than `uname`.
  Files actually read: No files read (data comes from environment variables or system calls)
- **rust** — the current rustup toolchain; it only reads files and spawns no subprocess, and what it reports is the toolchain name (`stable-x86_64-unknown-linux-gnu`) rather than the compiler version number.
  Files actually read: `$HOME/.rustup/settings.toml`
- **uptime** — time since boot.
  Files actually read: `/proc/uptime`
- **loadavg** — the 1 / 5 / 15 minute load averages; Linux only, on non-Linux it quietly produces no data, and the values keep the kernel's two decimal places as-is, with no rounding.
  Files actually read: `/proc/loadavg`
- **processes** — process count and thread count; neither number requires opening any process's files — the process count counts the pure-numeric directories under `/proc`, and the thread count takes the 4th field of `/proc/loadavg`.
  Files actually read: `/proc/loadavg`
- **init-system** — the name and version of process 1 (init); there is no fork-free universal source for the version, so it goes looking in the package database, and if no version is found it shows only the name (inside a container, what is shown is the container's process 1).
  Files actually read: `/proc/1/comm`

## CPU and Memory

- **cpu** — model and core count only, **no usage rate**: a collection tool gives a snapshot of "identity and capacity", and something like usage rate that changes from moment to moment belongs to htop/btop.
  Files actually read: `/proc/cpuinfo`, `/sys/devices/system/cpu/present`
- **cpu-cache** — the size and shared-core count of each CPU cache level; it reports "how many instances × how big each is" rather than total capacity, and since L3 is often shared by all cores, it does not write `1x` when the computed value is 1.
  Files actually read: `/sys/devices/system/cpu/cpu0/cache/index0/level`, `/sys/devices/system/cpu/cpu0/cache/index0/type`, `/sys/devices/system/cpu/cpu0/cache/index0/size`, `/sys/devices/system/cpu/cpu0/cache/index0/shared_cpu_list`, `/sys/devices/system/cpu/cpu0/cache/index1/level`, `/sys/devices/system/cpu/cpu0/cache/index1/type`, `/sys/devices/system/cpu/cpu0/cache/index1/size`, `/sys/devices/system/cpu/cpu0/cache/index1/shared_cpu_list`, `/sys/devices/system/cpu/cpu0/cache/index2/level`, `/sys/devices/system/cpu/cpu0/cache/index2/type`, `/sys/devices/system/cpu/cpu0/cache/index2/size`, `/sys/devices/system/cpu/cpu0/cache/index2/shared_cpu_list`, `/sys/devices/system/cpu/cpu0/cache/index3/level`, `/sys/devices/system/cpu/cpu0/cache/index3/type`, `/sys/devices/system/cpu/cpu0/cache/index3/size`, `/sys/devices/system/cpu/cpu0/cache/index3/shared_cpu_list`, `/sys/devices/system/cpu/online`
- **memory** — memory usage; reads `/proc/meminfo`, the same as Swap.
  Files actually read: `/proc/meminfo`
- **swap** — swap space usage; a machine with swap not enabled (`SwapTotal = 0`) returns **no data**, rather than `0 B / 0 B (0%)`.

## Disks and Filesystems

- **disk** — root filesystem usage; v0.1 looks at `/` only.
  Files actually read: `/proc/mounts`
- **physical-disk** — physical disks; the criterion is whether a `device` symlink exists, the capacity unit is fixed at 512-byte sectors, if the vendor/model cannot be read it falls back to the device name, and `loop*` and `dm-*` are excluded.

## Network

- **local-ip** — the local address, **the one used by the default route**; it is found out by "UDP connect route probing", sending no bytes at all, and without a default route (disconnected, loopback only, purely offline) there is no data; IPv4 is primary, falling back to IPv6 only when IPv4 cannot be obtained.
  Files actually read: `/proc/net/route`, `/sys/class/net/enp5s0f4u1u3c2/address`
- **net-io** — the network card's receive/transmit rates; the byte counters are cumulative values since boot, so it can only take the difference of two samples (the sampling interval is 200 ms, which under sequential scheduling makes the whole thing 200 ms slower), and it only reports the one network card on the default route.
  Files actually read: `/proc/net/route`, `/sys/class/net/enp5s0f4u1u3c2/operstate`, `/sys/class/net/enp5s0f4u1u3c2/statistics/rx_bytes`, `/sys/class/net/enp5s0f4u1u3c2/statistics/tx_bytes`
- **wifi** — the wireless card's status and signal; deciding "which interfaces are wireless" depends on whether the corresponding directory exists, signal quality and level have a data line only when connected, the SSID cannot be reported, and if there is not a single wireless card there is no data.
  Files actually read: `/proc/net/wireless`, `/sys/class/net/wlan0/operstate`
- **dns** — the name servers configured in `/etc/resolv.conf`; they are listed as-is in file order, neither sorted nor deduplicated, the keyword is case-sensitive, only when they are all loopback stubs does it switch to reading the file maintained by systemd-resolved, and with no `nameserver` line or no such file there is no data.
  Files actually read: `/etc/resolv.conf`
- **de** — the desktop environment; the clues and the version-number source are shared with session detection, and no desktop (a pure WM session, a TTY, a container) means no data.
  Files actually read: `/proc/658787/stat`, `/proc/658753/stat`, `/proc/217630/stat`, `/proc/217616/stat`, `/proc/217613/stat`, `/proc/97193/stat`, `/proc/97175/stat`, `/proc/1095/stat`
- **wm** — the window manager / compositor; the value is followed by the session type (the same Mutter is two different things on Wayland and X11), the session type comes from `XDG_SESSION_TYPE`, and if it cannot be read no parentheses are written.
  Files actually read: No files read (data comes from environment variables or system calls)

## Session, User, and Desktop Appearance

- **user** — the current user name; "who am I" is determined by uid, and environment variables are only a fallback.
  Files actually read: `/proc/self/status`, `/etc/passwd`
- **users** — the currently logged-in user sessions; the data source is that binary file rather than `who` (zero subprocesses), a bad record is skipped, only `USER_PROCESS` is counted, entries are deduplicated by user name and the most recent login is reported, if the timezone cannot be found the time is not printed and only the user name is reported; Debian/Ubuntu no longer write that file, so on such systems there is no data.
  Files actually read: `/var/run/utmp`, `/etc/localtime`
- **title** — `user@hostname`, the first line of the default view; the user name is determined by uid and the hostname comes from the nodename of `uname(2)`; note that this is not the "machine model" of the Host module — on a laptop the two are completely different.
  Files actually read: `/proc/self/status`, `/etc/passwd`
- **shell** — the shell the user is currently using; it reports only the name, not the version (getting the version would require running the shell itself, and this version spawns no subprocess).
  Files actually read: No files read (data comes from environment variables or system calls)
- **terminal** — the current terminal; the three sources are ordered by reliability (environment variable fingerprint → parent process chain → `$TERM` fallback), and no fork is done at any point.

- **locale** — the current locale; the order follows POSIX (`LC_ALL` > `LC_CTYPE` > `LANG`, the next one is only reached when the previous is non-empty), when not a single environment variable is present it falls back to the global configuration, and if that is still absent it counts as no data.

- **editor** — the default editor; the order follows POSIX, `$VISUAL` is for full-screen editors and `$EDITOR` is generic (the former is more specific), and the value is a **name**, not a path.

- **lm** — the login manager (display manager); all four sources are ordered by trustworthiness, and when all four are absent there is **no** display manager **installed**, at which point it reports `login` (this is not "could not find out", it is having found out "there is none"); the version is looked up in the package database, and it **can only report "which one is configured", not "which one is running right now"**.

## Peripherals and Display

- **display** — which monitors are connected, how big each is, and how many hertz; only when `status` is `connected` does a monitor count as connected, the first line of `modes` is the preferred mode (sysfs has no "current mode" field), and the refresh rate is only reported when the computed resolution matches the preferred mode.

- **keyboard** — keyboard devices; a keyboard is determined by its key bitmap rather than by `kbd` in `Handlers` (the power button also carries `kbd`), the value is the device name, numbering is applied only with multiple keyboards, and no index is written when there is only one.

- **mouse** — pointer devices (mice, touchpads, trackballs, touchscreens); the criterion is the buttons in the pointer range rather than the name (the keyboard inside a wireless receiver carries `BTN_0` but not `BTN_LEFT`, and is reported only under Keyboard), and numbering is applied only with multiple pointer devices.
  Files actually read: `/proc/bus/input/devices`
- **gamepad** — game controllers; the criterion is whether `js*` is present in `H: Handlers=` (`eventN` does not count — mice and keyboards have it open too), the value is the device name, and numbering is applied only with multiple controllers; this machine has no controller, hence no data.
  Files actually read: `/proc/bus/input/devices`
- **terminal-font** — the font the terminal itself uses; it is read from the terminal's own configuration file (no environment variable or `/proc` can tell it "which font am I using"), it **does not run `kitty +kitten`, does not run `fc-match`**, and an unrecognized terminal or a configuration with no font written is no data (**no guessing**: reporting something wrong is worse than not reporting).
  Files actually read: `$HOME/.config/kitty/kitty.conf`
- **terminal-size** — terminal size (columns × rows); it uses the same call as the one the text renderer measures width with, and when it cannot be obtained (output redirected, or not in a terminal at all) it returns no data.
  Files actually read: No files read (data comes from environment variables or system calls)
- **datetime** — the current local time; the standard library gives only UTC, the local time must be computed by reading the timezone database yourself, the timezone source is taken in order from `$TZ` or `/etc/localtime`, and if it truly cannot be read it falls back to UTC and says so in a variable, never blindly guessing an offset.
  Files actually read: `/etc/localtime`

## Packages and Managers

- **packages** — the number of installed packages, listed separately per package manager and sorted alphabetically by name (not by discovery order); package managers whose count is 0 do not appear in the result, and if none can be counted there is no data; flatpak counts only applications, not runtimes (this is a deliberate deviation).
  Files actually read: `/var/lib/dpkg/status`

## Layout Primitives

- **separator** — a horizontal line; it is a **render primitive**, not collected data (how long the line should be depends on how wide the other information lines are), so here it only emits an empty entry as a marker: the text renderer lays it out as a horizontal line, and the JSON renderer skips it outright.
  Files actually read: No files read (data comes from environment variables or system calls)
- **break** — an empty line; like separator it is a render primitive, but it does not even need a special case, and its reason for existing is to group information.
  Files actually read: No files read (data comes from environment variables or system calls)
- **colors** — a row of 16 color blocks; **the collector collects nothing**, this block is drawn entirely by the renderer (it emits an empty entry as a marker, and the renderer lays out two rows of color blocks when it sees this module), and it does not appear in JSON output.
  Files actually read: No files read (data comes from environment variables or system calls)

## Tips

- Name them with `--module`: `--module` takes a **list**, comma-separated, and only those modules are shown; the order is the order you wrote, and ones not present in the configuration can be named too.
- Division of work between `--sources` and `--explain`: `--explain` tells the **status** (shown / empty / skipped / failed), while `--sources` tells the **evidence** (which file was read). When both are given, the status is printed first, then the evidence. To distinguish "empty" from "shown", `--explain` has to actually run collection once, so it costs one collection's worth of time.
- The content of `--sources` is **recorded at runtime**, not a hand-written source table; the same module may read different paths on different machines (for example DMI, the connectors under `/sys/class/drm/`, and the devices under `/sys/class/power_supply/` all vary with the machine).
- To see structured results use `--json`; `--json` automatically turns off colors and the Logo.
